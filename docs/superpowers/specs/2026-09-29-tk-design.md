# `:Tk` — Neovim front end for the tk ticket CLI

- Status: implemented (`lua/config/tk.lua`), manual testing pending
- Created: 2026-09-29
- tk: [wedow/ticket](https://github.com/wedow/ticket) 0.3.2

## Goal

Read and triage `tk` tickets from Neovim. Agents create and edit tickets through the CLI; in Neovim the user mostly browses, reads, and changes status. No existing Neovim plugin covers `tk`.

## Non-goals

- Dependency/link wiring from the picker (use `:Tk dep …` / `:Tk link …`)
- Editing frontmatter fields through UI
- Statusline component, "active ticket" tracking
- Ticket titles in command-line completion

## Files

- `lua/config/tk.lua` — the whole feature. `M.setup()` does nothing unless `tk` is on `$PATH` (`vim.fn.executable`); otherwise it only registers `:Tk` and the completion cache's `CmdlineLeave` autocmd; `tk help`, Snacks and ticket files are loaded on first use.
- `init.lua` — `require("config.tk").setup()`, next to `lsp_mute`

No new plugin dependencies; uses Snacks picker and `Snacks.win`, `vim.system`, `vim.ui.input`/`vim.ui.select`.

## `:Tk` command

One user command, `nargs = "*"`, with completion.

- `:Tk` — opens the ticket picker
- `:Tk <sub> [args…]` — runs `tk <sub> [args…]` after placeholder filling (below)

Arguments are split from the raw `opts.args` honoring `"…"` quotes, not from `opts.fargs` (which splits on every space), so `:Tk create -t bug "fix thing"` reaches tk as intended. `'` is not a quote, so `:Tk add-note don't forget` keeps its apostrophe. An unbalanced `"` is an error and nothing runs. Neither Neovim nor Snacks has a public shell-style splitter, so this is local.

### Context

Computed once per invocation (and once per command-line session for completion), then shared by placeholder filling, the pickers and completion. Nothing depends on Neovim's cwd being the project root (no reliance on this config's autochdir), so the module can later become a standalone plugin.

- Ticket buffer: the current buffer's file is `<dir>/<id>.md` where `<dir>` is `$TICKETS_DIR` or named `.tickets`; `<id>` is the current ticket
- Tickets directory: the ticket buffer's `<dir>`; otherwise `$TICKETS_DIR` if set; otherwise the nearest `.tickets/` upward from Neovim's cwd (`vim.fs.find`, `upward = true`, `type = "directory"`), matching tk's `find_tickets_dir`. Not `utils.find_project_root`: it stops at `~` and caches misses.
- tk's environment: `env = { TICKETS_DIR = <tickets directory> }`, since tk prefers `$TICKETS_DIR` over its cwd; `cwd` = the tickets directory's parent when it is named `.tickets`, else Neovim's cwd. tk takes new IDs' prefix from `basename $PWD`, so running from a subdirectory would make `lua-ab12` instead of `nvi-ab12`. With no tickets directory yet (`create`), tk runs in Neovim's cwd.
- Tickets: every `*.md` in the tickets directory, parsed once (see Data)
- Prefixes: the part before the first `-` of each ticket ID
- `resolve(arg)`: a full ID, or exactly the part after the prefix dash (`z7n3` → `nvi-z7n3`; two prefixes sharing a hash is an error). Stricter than tk's `ticket_path` substring match: no partial IDs. Every ID slot goes through it (see Placeholder filling).

### Running tk

`vim.system` with `cwd` and `env` from Context and an `on_exit` callback (via `vim.schedule`), since tk forks awk/sed/jq per call. The one synchronous call is `tk help` (about 8 ms, once per session): completion must return candidates immediately.

- Exit 0, output of at most one line: `vim.notify` at info level, prefixed with the command that ran (`tk start nvi-u34b`)
- Exit 0, longer output: `Snacks.win` float with `ft = "markdown"` (`show`, `ls`, `ready`, `dep tree`, …)
- Non-zero exit: `vim.notify` at error level with stderr

### Overrides

Passing these through would not work, so they are handled locally. Each is a flag in one `OVERRIDES` table keyed by subcommand, which holds all tk behaviour that `tk help` does not show:

- `edit` — `:edit` the resolved ticket's file. Without a terminal, tk 0.3.2 only prints `Edit ticket file: <path>`.
- `create`, `migrate-beads` — tk silently creates `.tickets/` in its cwd when none is found (its `WRITE_COMMANDS`). When the tickets directory is missing, first ask `Create .tickets/ in <full path>?`; declining runs nothing. After `create`, `:edit <tickets dir>/<id from stdout>.md`.
- `add-note` — without text, ask with `vim.ui.input`; empty or cancelled input runs nothing. tk would otherwise read the note from stdin, which is not a TTY under `vim.system`, and append an empty note.

## Usage table from `tk help`

`tk help` is parsed on first use and cached for the session. A usage line has a two-space indent and does not start with `-` (the indented option lines under `create` are skipped). The gap before the description is sometimes a single space (`create [title] [options] Create ticket…`), so lines are read token by token:

1. Leading lowercase words (`[a-z][a-z|-]*`) are subcommand words (`start`, `dep tree`, `migrate-beads`); `a|b` means aliases (`ls|list`). Descriptions start uppercase, which ends a placeholder-less usage like `dep cycle` (true for every line in tk 0.3.2).
2. Then `<…>` and `[…]` groups, each read to its closing bracket. Flag groups (`[--full]`, `[-a X]`) and `[options]` are skipped.
3. The first other token starts the description.

Remaining groups are placeholders, in order: `<name>` required, `[name]` optional, `[name...]` variadic. Kind:

- ID — name is `id` or ends in `-id` (`<dep-id>`, `<target-id>`, `[id...]`)
- status — `<status>`; values parsed from the description's `(open|in_progress|closed)`
- text — anything else

When several usages share a first word (`dep`, `dep tree`, `dep cycle`), the one with the most literal words that all match the typed arguments wins, which is tk's own dispatch order: `:Tk dep tree` is `dep tree`, `:Tk dep nvi-z7n3` is `dep`. Commands whose usage has no ID placeholder are passed through as split, and so are subcommands missing from `tk help` (tk rejects them with its own error).

### Parse failures are loud

The parser depends on tk 0.3.2's help format, so it fails loudly rather than guessing. Any of these is an error naming the offending line, raised on every `:Tk` invocation and completion until fixed; nothing is run or offered:

- `tk help` exits non-zero
- no usage lines found
- an unclosed `<` or `[`
- a usage line with more than two subcommand words or an empty description (a description starting lowercase is read as subcommand words and ends up here)

## Placeholder filling

Typed arguments fill placeholders left to right, as on the command line. In usages that list flag groups (`dep tree [--full]`), arguments starting with `-` pass through and fill no slot; elsewhere they are ordinary arguments, so `:Tk add-note -1 from me` is a note. Arguments left over after all placeholders are passed to tk after the filled ones (so `:Tk add-note looks good` sends both words), and tk reports anything it rejects.

- ID slot: the argument is `resolve()`d and tk receives the full ID. One that does not resolve is an error and nothing runs, so typos never reach tk. IDs are typed in full (`nvi-z7n3`) or without the prefix (`z7n3`); nothing shorter matches, completion fills them in.
- Whether the next argument goes into an ID slot at all is only a question when a non-ID slot follows (`status <id> <status>`, `add-note <id> [text]`): the argument is the ID if it resolves or is ID-shaped, i.e. starts with a known prefix and a dash (`nvi-…`), so a typo like `nvi-z7n4` errors instead of becoming note text. Otherwise the ID is missing and the argument fills the next slot: `:Tk status closed`, `:Tk add-note looks good`. A note or status word equal to an existing hash (`open`, `done`) would be read as that ticket; with 4-character hashes this is accepted.
- Other slot: consumes the next argument. `<status>` must be one of its parsed values, otherwise error. A missing `<status>` is asked with `vim.ui.select` over those values; cancelling runs nothing.

### Missing IDs

- Exactly one ID slot (`start`, `close`, `reopen`, `show`, `status`, `add-note`, `edit`, `dep tree`): filled with the current ticket in a ticket buffer, otherwise a picker opens.
- Two or more ID slots (`dep`, `undep`, `unlink`): never auto-filled; each missing slot opens a picker, in order.
- Variadic ID tail (`link <id> <id> [id...]`): all missing slots are filled by one multi-select picker (`<Tab>`). Fewer selections than missing required slots: error, nothing runs.

### Duplicate IDs

No command takes the same ticket twice: tk 0.3.2 does not check, so `dep X X` and `link X X` write self-references (a self-dep shows the ticket as blocked forever). If two ID slots resolve to the same ticket, the command errors and nothing runs. Slot pickers exclude tickets already used in the command.

### Examples

These double as the manual test checklist. In the buffer for `nvi-u34b`:

| Typed | Runs |
|---|---|
| `:Tk start` | `tk start nvi-u34b` |
| `:Tk status closed` | `tk status nvi-u34b closed` |
| `:Tk add-note looks good` | `tk add-note nvi-u34b looks good` |
| `:Tk status` | status select, then `tk status nvi-u34b <picked>` |
| `:Tk add-note don't forget` | `tk add-note nvi-u34b don't forget` |
| `:Tk add-note` | input prompt; empty input runs nothing |
| `:Tk start nvi-z7n3` | `tk start nvi-z7n3` |
| `:Tk show z7n3` | `tk show nvi-z7n3` |
| `:Tk show z7` | error (no ticket `z7`), nothing runs |
| `:Tk status nvi-z7n3` | status select, then `tk status nvi-z7n3 <picked>` |
| `:Tk status z7n3 closed` | `tk status nvi-z7n3 closed` |
| `:Tk add-note nvi-z7n3 done` | `tk add-note nvi-z7n3 done` |
| `:Tk add-note z7n3 done` | `tk add-note nvi-z7n3 done` |
| `:Tk dep nvi-z7n3` | picker for `‹dep-id›` (without `nvi-z7n3`), then `tk dep nvi-z7n3 <picked>` |
| `:Tk dep nvi-u34b u34b` | error, nothing runs |
| `:Tk dep tree` | `tk dep tree nvi-u34b` |
| `:Tk dep cycle` | `tk dep cycle` |
| `:Tk ready` | `tk ready` |
| `:Tk close nvi-z7n4` (typo) | error, nothing runs |
| `:Tk status nvi-z7n4 closed` (typo) | error, nothing runs |

Outside a ticket buffer, `:Tk start` opens a picker for `‹id›`.

## Completion

Position-aware: the typed arguments go through placeholder filling, and completion offers candidates for the next slot's kind.

| Next slot | Offers |
|---|---|
| subcommand (first argument) | subcommands and aliases |
| after a first word shared by several usages (`dep`) | their next literal words (`tree`, `cycle`), plus the candidates for `dep`'s own next slot |
| ID, incl. variadic tail (`add-note`'s first argument too) | ticket IDs (closed too, so `reopen` works) whose full ID or part after the prefix dash starts with the typed text |
| ID followed by `<status>` (`status`) | statuses matching the typed prefix; if none match, matching IDs. Empty: statuses, then IDs |
| `<status>` | its parsed values |
| anything else | nothing |

Candidates are always full IDs, so `:Tk add-note u<Tab>` completes to `nvi-u34b` (and `:Tk status z<Tab>` to `nvi-z7n3`), which then fills the ID slot. `:Tk status c<Tab>` gives `closed`; `ci` matches no status and offers `cia-*` IDs. IDs and statuses are not mixed for a non-empty prefix because the cmdline `<Tab>` accepts the top item and blink orders by its own score.

Completion returns plain strings, so the menu shows IDs without titles; the picker is for finding tickets by title. blink.cmp's cmdline menu calls completion on every keystroke, so the Context (tickets directory, IDs, prefixes) is cached until `CmdlineLeave`.

## Ticket picker

Snacks picker; shared by `:Tk` and the slot pickers. Items set an absolute `file`; `cwd` is a picker option, since Snacks joins `item.cwd .. "/" .. item.file`.

### Data

Read from `.tickets/*.md` directly, not through tk: `tk query` emits unescaped JSON (a `"` in any field breaks the line) and has no title, and `tk ls` appends ` <- [deps]` to titles. Each file is read line by line up to its first `# ` heading.

- Frontmatter: flat `key: value` lines, lists as `[a, b]` — the same subset tk's own `yaml_field` reads
- Title: the first `# ` heading
- Priority: `tonumber(v) or 2` (tk's default)
- Blocked: a flag, not a status — open or in-progress with any dep whose status is not `closed`, via an id→status map

### List line

```
◐ P1 bug   hbr-18dq  Sort backend addresses before building Maglev table (UDP)   xdp udp maglev
○ P2 task  nvi-z7n3  kulala.nvim upstream gone: monitor, then fork vs replace
⊘ P2 task  nvi-ab12  …
```

- Status icon: `○` open, `◐` in progress, `●` closed; a blocked open ticket shows `⊘` instead of `○`, a blocked in-progress ticket keeps `◐`
- Priority `P0`–`P4`, highlighted by urgency
- Type, ID (dimmed), title, tags (comment highlight)
- Closed tickets dimmed
- Searchable text includes the status word (`open`, `in_progress`, `closed`), `blocked` when flagged, type and tags, so typing filters by them

Sort: in progress, then open, then closed (grouped by status; blocked does not move a ticket); within a group by priority, then newest first, then ID so tickets created in the same second keep a stable order. Built with Snacks field sort (`sort.fields = { "score:desc", "group", "priority", "created:desc", "id" }`) and `matcher.sort_empty = true`, so the order also holds with an empty search.

### Preview

`Snacks.picker.preview.cmd({ "tk", "show", id }, ctx, { term = false })`, with markdown treesitter started on the job's buffer; `ft = "markdown"` would use Snacks' own renderer instead. Async, cancelled on cursor move, runs in the picker's `cwd` with Context's `env`. Shows the ticket file plus tk's computed Blockers / Blocking / Children / Linked sections with titles.

### Keys

Snacks defaults stay; `<CR>` opens the ticket file (default action, via `item.file`). One addition: `<a-a>`, not bound by Snacks picker defaults or this config, opens an action menu (`vim.ui.select`) for the ticket under the cursor:

| Status | Entries |
|---|---|
| open | Start, Close, Add note |
| in_progress | Stop, Close, Add note |
| closed | Reopen, Add note |

Entries run through the same path as `:Tk` (`start`, `close`, `reopen`, `add-note` with the ticket's ID; Stop is `status <id> open`), so Add note gets the `add-note` prompt. In tk's `on_exit`, the list refreshes: the finder re-reads the ticket files (not the cached Context), and the cursor follows the acted-on ticket by ID, since a status change re-sorts it. `picker:refresh()` alone keeps the row number and would land on another ticket.

### Slot mode

When filling a placeholder, the picker:

- reuses the list and preview
- is titled with the command so far and the slot: `tk dep nvi-z7n3 ‹dep-id›`
- excludes tickets already used in the command
- confirms the selection on `<CR>` (multi-select with `<Tab>` for a variadic tail)
- has no `<a-a>` menu
- cancels the whole command when closed

## Testing

Manual, in `~/.config/nvim/.tickets` (no Lua test setup in this repo):

- Every row of the Examples table, inside and outside a ticket buffer
- `:Tk` — list order, icons, dimmed closed tickets, filtering by typing `blocked`/`in_prog`, preview sections
- `<a-a>` on open, in-progress and closed tickets; the list refreshes with the new status and the cursor stays on the same ticket
- Blocked in-progress ticket shows `◐`, sorts with in-progress, matches both `in_prog` and `blocked`
- `:Tk dep <Tab>` offers `tree` and `cycle`
- `:Tk link` multi-select; cancelling any picker runs nothing
- `:Tk start` in a ticket buffer from another repo acts on that repo, also with `$TICKETS_DIR` exported
- `:Tk create` with Neovim's cwd in a subdirectory gets the project's prefix
- `:Tk edit`, `:Tk create "title"` open the file; `:Tk create` outside a project asks first, naming the path
- Completion for subcommands, IDs, statuses; `:Tk status c<Tab>` gives `closed`, a prefix matching no status gives IDs; `:Tk add-note u<Tab>` gives `nvi-u34b` (check blink's own fuzzy filter keeps candidates matched after the prefix dash)
- Error path: `:Tk ls` in a directory without `.tickets/`
- `stylua --check .` and `selene .`
